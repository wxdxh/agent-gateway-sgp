Step 1 of 9 ⏱ 예상 소요 시간: 5분

개요 및 제로 트러스트 에이전트 거버넌스 아키텍처

엔터프라이즈 환경에서 대규모 언어 모델(LLM) 기반의 자율형 에이전트(Autonomous AI Agent)는 단순 질의응답을 넘어 데이터베이스 조회, 실시간 자금 이체, 공과금 결제와 같은 핵심 프로덕션 API를 직접 호출합니다. 그러나 전통적인 IAM 및 RBAC(역할 기반 접근 제어)만으로는 에이전트가 도구를 어떤 맥락과 파라미터(예: $2,000 고액 이체)로 호출하는지 통제할 수 없습니다.

💡 비즈니스 시나리오: Apex Wealth Management

글로벌 자산관리 기업인 Apex Wealth Management는 고객이 계좌 잔액을 조회하고 전화번호 기반 송금을 수행할 수 있도록 Conversational Banking Agent를 도입하고자 합니다. 보안 및 규정 준수 팀은 에이전트 애플리케이션 코드를 수정하지 않고도 "1회 이체 금액이 1,000 USD를 초과하는 모든 거래를 네트워크 경계에서 원천 차단"하고 모든 판정 근거를 감사 로그에 남기는 아키텍처를 요구합니다.

전체 시스템 아키텍처 (Google Cloud 아이콘 다이어그램)

하이브리드 네트워킹 및 Private Service Connect 구성 (02-setup-networking.sh)

Google 관리형 Agent Gateway가 고객 VPC 내부로 트래픽을 라우팅하고, 비공개 전용망(Private Service Connect)을 통해 시맨틱 거버넌스 정책(SGP) 엔진과 통신할 수 있도록 네트워크 브리지를 구축합니다.

[그림 2] 하이브리드 VPC 네트워크 어태치먼트 및 Private Service Connect (PSC) 토폴로지

1. 네트워크 구성 스크립트 실행 (02-setup-networking.sh)

아래 스크립트는 4가지 핵심 네트워크 리소스를 순서대로 생성합니다. 특히 프로젝트마다 할당되는 SGP 엔진의 PSC Service Attachment URI를 자동으로 감지하여 연결합니다.

Bash — Step 2 네트워킹 구성 실행 
./02-setup-networking.sh

2. 세부 리소스 구성 내역

02-setup-networking.sh — 핵심 명령어 구조 
# 1. 리전 관리형 프록시 전용 서브넷 생성
gcloud compute networks subnets create agent-gateway-proxy-subnet \
  --project="${PROJECT_ID}" \
  --region="${LOCATION}" \
  --network="${NETWORK_NAME}" \
  --purpose=REGIONAL_MANAGED_PROXY \
  --role=ACTIVE \
  --range=10.11.13.0/24

# 2. Agent Gateway가 VPC에 진입하기 위한 Network Attachment 생성
gcloud compute network-attachments create agent-gateway-na \
  --project="${PROJECT_ID}" \
  --region="${LOCATION}" \
  --subnets="${SUBNET_NAME}" \
  --connection-preference=ACCEPT_AUTOMATIC

# 3. SGP 엔진 연결용 내부 정적 IP 예약 및 PSC 엔드포인트 생성
gcloud compute addresses create sgp-psc-ip \
  --project="${PROJECT_ID}" \
  --region="${LOCATION}" \
  --subnet="${SUBNET_NAME}"

gcloud compute forwarding-rules create sgp-psc-endpoint \
  --project="${PROJECT_ID}" \
  --region="${LOCATION}" \
  --network="${NETWORK_NAME}" \
  --address=sgp-psc-ip \
  --target-service-attachment="${SERVICE_ATTACHMENT}"

# 4. policy.internal. 프라이빗 DNS 존 및 A 레코드 등록
gcloud dns managed-zones create policy-internal-zone \
  --project="${PROJECT_ID}" \
  --dns-name="policy.internal." \
  --visibility="private" \
  --networks="${NETWORK_NAME}"
✅ 검증 가이드라인: PSC 연결 상태 확인

스크립트 완료 후 아래 명령어를 실행했을 때 pscConnectionStatus가 반드시 ACCEPTED로 표시되어야 합니다:
gcloud compute forwarding-rules describe sgp-psc-endpoint --region=us-central1 --format="value(pscConnectionStatus)"

Step 4 of 9 ⏱ 예상 소요 시간: 5분

Agent Gateway 및 콘텐츠 인가 정책 구성 (03-setup-agent-gateway.sh)

네트워크 브리지가 준비되었으므로, 이제 에이전트의 모든 외부 호출을 가로채는 Agent Gateway(agent-egress)를 생성하고, 모델/도구 호출 페이로드를 policy.internal:443(SGP 엔진)으로 전달해 인가 여부를 판단하는 Content Authz Policy를 바인딩합니다.

1. Agent Gateway 및 정책 배포 실행

Bash — Step 3 스크립트 실행 
./03-setup-agent-gateway.sh

2. 구성되는 3대 핵심 리소스 명세

① Service Callout Authorization Extension (sgp-authzextension)

게이트웨이가 인가 결정을 내릴 때 호출할 외부 확장 프로그램으로 policy.internal:443을 등록합니다.

Bash — Authz Extension 생성 
gcloud service-extensions authz-extensions create sgp-authzextension \
  --project="${PROJECT_ID}" \
  --location="${LOCATION}" \
  --load-balancing-scheme=INTERNAL_MANAGED \
  --authority="policy.internal" \
  --service="policy.internal:443" \
  --timeout="10s" \
  --fail-open=false \
  --forward-headers=""

② Egress Agent Gateway (agent-egress)

AGENT_TO_ANYWHERE 거버넌스 경로를 사용하여 에이전트에서 나가는 트래픽을 관리하며, policy.internal. 도메인을 고객 VPC의 Cloud DNS로 피어링합니다.

YAML — agent-gateway-vpc-egress.yaml 
name: projects/${PROJECT_ID}/locations/${LOCATION}/agentGateways/agent-egress
protocols:
  - MCP
googleManaged:
  governedAccessPath: AGENT_TO_ANYWHERE
registries:
  - //agentregistry.googleapis.com/projects/${PROJECT_ID}/locations/${LOCATION}
networkConfig:
  egress:
    networkAttachment: projects/${PROJECT_ID}/regions/${LOCATION}/networkAttachments/agent-gateway-na
  dnsPeeringConfig:
    domains:
      - policy.internal.
    targetProject: ${PROJECT_ID}
    targetNetwork: projects/${PROJECT_ID}/global/networks/${NETWORK_NAME}

③ Content Authz Policy (agent-egress-sgp-authzpolicy)

CEL(Common Expression Language) 조건식을 사용하여 :generateContent 및 :streamGenerateContent 호출을 감지하고 sgp-authzextension으로 라우팅합니다.

YAML — agent-egress-sgp-authzpolicy.yaml 
name: projects/${PROJECT_ID}/locations/${LOCATION}/authzPolicies/agent-egress-sgp-authzpolicy
target:
  loadBalancingScheme: LOAD_BALANCING_SCHEME_UNSPECIFIED
  resources:
    - "projects/${PROJECT_NUM}/locations/${LOCATION}/agentGateways/agent-egress"
httpRules:
  - to:
      operations:
        - paths:
            - prefix: "/"
    when: '!request.headers["content-type"].startsWith("application/grpc") && (request.path.endsWith(":generateContent") || request.path.endsWith(":streamGenerateContent"))'
action: CUSTOM
policyProfile: CONTENT_AUTHZ
customProvider:
  authzExtension:
    resources:
      - "projects/${PROJECT_NUM}/locations/${LOCATION}/authzExtensions/sgp-authzextension"
⚠️ 중요 가이드라인: Fail-Closed 보안 설정

--fail-open=false로 설정되어 있으므로, SGP 정책 엔진과의 통신이 실패하거나 정책 위반으로 판정될 경우 요청은 기본적으로 차단(Fail-Closed)되어 금융 사고를 예방합니다.

Banking MCP 서버 빌드 및 Cloud Run 배포 (04-deploy-mcp.sh)

에이전트가 사용할 백엔드 뱅킹 도구들을 제공하는 Model Context Protocol (MCP) 서버를 Cloud Run에 배포합니다. 이 서버는 인메모리 원장(Ledger)을 기반으로 계좌 조회, 전화번호 기반 고객 검색, 자금 이체, 공과금 납부 기능을 제공합니다.

1. 제공되는 4대 뱅킹 MCP 도구 명세

도구 이름 (Tool Name) 필수 파라미터 기능 설명
get_account customer_id (예: CUST005) 고객 ID에 대한 계좌 번호, 상태, 현재 잔액(초기값 $10,000.00 USD)을 반환합니다.
lookup_customer_by_phone phone (예: 555-0001) 수취인의 전화번호로 고객 이름과 계좌 정보를 식별합니다.
transfer_to_phone customer_id, target_phone, amount 고객 계좌에서 수취인 전화번호 계좌로 지정 금액을 이체하고 거래 번호(TXN-...)를 발급합니다.
pay_bill customer_id, biller_name, account_number, amount 가맹점 또는 공과금 청구서를 결제하고 잔액을 차감합니다.

클라우드 배포 전 로컬에서 MCP 서버의 도구 스키마와 JSON-RPC 2.0 핸들러를 즉시 검증할 수 있습니다.

Bash — 로컬 MCP 서버 프로토콜 테스트

04-deploy-mcp.sh를 실행하면 Cloud Build를 통해 컨테이너를 빌드하고 Cloud Run 서비스(banking-mcp-server)로 배포한 뒤, 엔드포인트 URL을 .env.runtime에 자동 저장합니다.

에이전트가 하드코딩된 URL에 의존하지 않고 중앙 집중식으로 관리되는 카탈로그에서 도구를 발견할 수 있도록 Google Cloud Agent Registry에 Banking MCP 서버와 시스템 엔드포인트를 등록합니다.

1. Agent Registry 등록 스크립트 실행

Bash — Step 5 스크립트 실행 
./05-register-mcp.sh

2. 왜 Google Cloud 시스템 엔드포인트 4종을 함께 등록해야 하나요?

Agent Gateway가 AGENT_TO_ANYWHERE 모드로 동작할 때는 기본 거부(Default-Deny) 정책이 적용되어, Agent Registry에 명시적으로 등록되지 않은 외부 엔드포인트로의 모든 통신이 차단됩니다. 따라서 에이전트 런타임이 정상 가동되기 위해 필요한 아래 4개의 Google Cloud 시스템 엔드포인트를 함께 등록합니다:

등록 서비스 ID 표시 이름 (Display Name) 허용 엔드포인트 URL 용도
google-oauth2 Google OAuth2 Token Endpoint https://oauth2.googleapis.com 서비스 계정 인증 토큰 발급 및 갱신
google-cloud-logging Google Cloud Logging API https://logging.googleapis.com 에이전트 런타임 실행 로그 기록
google-telemetry Google Cloud Telemetry API https://telemetry.googleapis.com OpenTelemetry 트레이스 및 메트릭 수집
google-aiplatform Google Cloud AI Platform API https://us-central1-aiplatform.googleapis.com Gemini 2.5 Flash 모델 추론 API 호출

Vertex AI Agent Runtime에 ADK 에이전트 배포 (06-deploy-agent.sh)

🚨 필수 주의사항: 배포에 15분 이상 소요됩니다 (절대 중단하지 마세요)

Vertex AI Agent Runtime(Reasoning Engine)은 컨테이너 이미지 빌드, 보안 샌드박스 프로비저닝, 네트워크 어태치먼트 및 Agent Gateway 프록시 마운트, 그리고 Agent Identity(SPIFFE/Workload Identity) 발급을 수행합니다. 이 과정은 보통 15분에서 최대 20분이 소요되므로 터미널을 닫거나 Ctrl+C로 중단하지 마세요.

1. Conversational Banking 에이전트 핵심 구조 (app/agent.py)

에이전트는 Google Agent Development Kit (ADK)와 gemini-2.5-flash 모델을 사용하며, ApiRegistry를 통해 Agent Registry에 등록된 Banking MCP Server의 도구 세트를 동적으로 가져옵니다.

Python — conversational-banking/app/agent.py 핵심 발췌 
from google.adk.agents import Agent
from google.adk.tools.api_registry import ApiRegistry

# Agent Registry에서 MCP 서버의 도구 세트를 동적으로 로드
api_registry = ApiRegistry(
    api_registry_project_id=PROJECT_ID,
    location=LOCATION,
)
banking_tools = api_registry.get_toolset(mcp_server_name=MCP_SERVER_NAME)

root_agent = Agent(
    name="conversational_banking",
    model=Gemini(model="gemini-2.5-flash"),
    instruction="""You are a professional, helpful conversational banking assistant for Apex Wealth Management.
    ...
    4. POLICY COMPLIANCE: If a tool call is blocked or denied by a governance policy,
       politely inform the user that the transaction cannot be completed and clearly state the exact reason.""",
    tools=[banking_tools],
)

2. 엔터프라이즈 런타임 환경을 위한 핵심 엔지니어링 처리

🔒 Agent Gateway TLS 프록시 호환성

Agent Gateway가 HTTPS 이그레스 트래픽의 페이로드를 검사할 때 자체 서명된 인터셉트 인증서를 사용하므로, 에이전트 컨테이너의 HTTP 클라이언트(httpx, requests)가 프록시 경유 시 SSL 검증 오류 없이 통신하도록 구성되어 있습니다.

🪪 Cloud Run MCP 호출용 OIDC ID 토큰 자동 주입

Cloud Run에 배포된 banking-mcp-server를 호출할 때 메타데이터 서버에서 대상 URL을 Audience로 하는 OIDC ID 토큰을 발급받아 Authorization: Bearer 헤더에 자동으로 주입합니다.

Step 8 of 9 ⏱ 예상 소요 시간: 3분

시맨틱 거버넌스 정책(SGP) 생성 (07-create-sgp-policy.sh)

이제 에이전트 코드나 MCP 서버 코드를 단 한 줄도 수정하지 않고, 자연어 제약 조건(Natural Language Constraint)만으로 1,000 USD를 초과하는 모든 송금 요청을 차단하는 시맨틱 거버넌스 정책(high-value-limit)을 생성합니다.

1. SGP 정책 생성 스크립트 실행

Bash — Step 7 스크립트 실행 
./07-create-sgp-policy.sh

2. SGP 정책 생성 명령어 상세 분석

07-create-sgp-policy.sh — gcloud beta ai semantic-governance-policies 
# ADK는 MCP 서버 이름을 기반으로 도구 이름 앞에 접두사(Banking_MCP_Server_)를 부여합니다.
TOOL_NAME="Banking_MCP_Server_transfer_to_phone"

gcloud beta ai semantic-governance-policies create high-value-limit \
  --project="${PROJECT_ID}" \
  --location="${LOCATION}" \
  --display-name="High Value Transfer Limit" \
  --agent="projects/${PROJECT_ID}/locations/${LOCATION}/agents/${AGENT_ID}" \
  --mcp-tools="mcp-server=projects/${PROJECT_ID}/locations/${LOCATION}/mcpServers/${MCP_SERVER_NAME},tools=${TOOL_NAME}" \
  --natural-language-constraint="Block any transfer value exceeding USD 1000."
💡 실무 핵심 팁: ADK 런타임 도구 네임스페이스 매칭

ADK의 ApiRegistry.get_toolset()은 Agent Registry의 MCP 서버 표시 이름(Banking MCP Server)을 정규화하여 런타임 도구 호출 시 Banking_MCP_Server_transfer_to_phone이라는 액션 이름을 생성합니다.
따라서 SGP 정책의 tools 파라미터에 Banking_MCP_Server_transfer_to_phone을 지정해야 SGP 엔진이 해당 도구 호출에 대해 자연어 제약 조건을 정확히 매칭하여 평가합니다. (정책 생성 후 파드 동기화에 약 15~30초가 소요됩니다.)
