개요: 에이펙스 자산운용의 자율형 AI 에이전트 거버넌스

금융권에서 자율형 AI 에이전트가 단순 상담을 넘어 계좌 잔액 조회, 실시간 계좌 이체, 공과금 납부와 같은 핵심 원장 API를 직접 호출하기 시작하면서, 전통적인 IAM 권한 제어만으로는 "누가 호출했는가"만 확인할 뿐 "얼마를 어떤 맥락으로 이체하려 하는가"를 통제하기 어렵습니다.

🏦 비즈니스 시나리오: 에이펙스 자산운용 (Apex Asset Management)

국내 금융사인 에이펙스 자산운용은 고객이 대화만으로 간편 송금과 계좌 관리를 수행할 수 있도록 Gemini Enterprise 기반의 대화형 뱅킹 에이전트를 도입했습니다.
금융보안 및 준법감시팀은 보이스피싱 및 고액 오송금 사고를 예방하기 위해, 에이전트 코드를 수정하지 않고도 "1회 이체 금액이 100만 원(1,000,000 KRW / 1,000 USD)을 초과하는 모든 송금 요청을 네트워크 경계에서 즉시 차단"하는 제로 트러스트 아키텍처를 구축하고자 합니다.

전체 시스템 아키텍처

Gemini Enterprise Agent Runtime에서 실행되는 에이전트의 모든 외부 도구 호출은 Google Cloud Agent Gateway에 의해 가로채어지며, 비공개 전용망(PSC)으로 연결된 시맨틱 거버넌스 정책(SGP) 엔진이 허용(ALLOW) 판정을 내린 요청만 백엔드 Cloud Run 뱅킹 MCP 서버에 도달합니다.

사전 준비 및 프로젝트 환경 / IAM 설정 (01-setup-env.sh)

실습 레포지토리를 복제하고 공통 환경 변수를 로드한 뒤, Gemini Enterprise, Agent Gateway, Agent Registry에 필요한 Google Cloud API와 서비스 에이전트 권한을 활성화합니다.

1. 레포지토리 클론 및 스크립트 실행

Bash — 레포지토리 클론 및 Step 1 스크립트 실행 
git clone https://github.com/wxdxh/agent-gateway-sgp.git
cd agent-gateway-sgp

gcloud auth login
gcloud auth application-default login
export PROJECT_ID="your-gcp-project-id"
gcloud config set project "${PROJECT_ID}"

# API 활성화 및 IAM 권한 구성 실행
./01-setup-env.sh
🔍 스크립트 내부 구동 원리 해설 (env.sh & 01-setup-env.sh)

단순히 ./01-setup-env.sh를 실행하는 것만으로 내부에서는 다음 2가지 핵심 자동화 작업이 수행됩니다.

① 프로젝트 번호 및 활성 VPC 자동 탐지 (env.sh)

모든 스크립트가 최상단에서 불러오는 env.sh는 프로젝트 번호(PROJECT_NUM)를 조회하여 Google 관리형 게이트웨이 서비스 계정(AGW_SA)을 조합하고, default 네트워크가 없는 기업 환경에서도 첫 번째 활성 VPC와 서브넷을 자동으로 찾아 연결합니다.

env.sh — 핵심 환경 변수 자동 구성 로직 
export PROJECT_ID="${PROJECT_ID:-$(gcloud config get-value project 2>/dev/null)}"
export PROJECT_NUM="$(gcloud projects describe "${PROJECT_ID}" --format="value(projectNumber)")"
export LOCATION="${LOCATION:-us-central1}"
export AGW_SA="serviceAccount:service-${PROJECT_NUM}@gcp-sa-agentgateway.iam.gserviceaccount.com"

# default VPC 유무 확인 및 활성 VPC/서브넷 자동 폴백(Fallback)
if gcloud compute networks describe default --project="${PROJECT_ID}" &>/dev/null; then
  DEFAULT_NET="default"; DEFAULT_SUBNET="default"
else
  DEFAULT_NET="$(gcloud compute networks list --project="${PROJECT_ID}" --format="value(name)" | head -n 1)"
  DEFAULT_SUBNET="$(gcloud compute networks subnets list --project="${PROJECT_ID}" --regions="${LOCATION}" --network="${DEFAULT_NET}" --format="value(name)" | head -n 1)"
fi

② Network Services 서비스 에이전트 프로비저닝 및 IAM 바인딩 (01-setup-env.sh)

16개 필수 API를 활성화한 직후, gcloud beta services identity create 명령으로 Google 관리형 서비스 에이전트 ID를 생성하고 3가지 필수 IAM 역할을 부여합니다.

01-setup-env.sh — 서비스 ID 생성 및 IAM 부여 코드 
# 1. Network Services 관리형 서비스 에이전트 ID 명시적 생성
gcloud beta services identity create \
  --service=networkservices.googleapis.com \
  --project="${PROJECT_ID}" || true

# 2. Agent Gateway 서비스 에이전트에 3대 핵심 IAM 역할 부여
for ROLE in "roles/agentgateway.serviceAgent" "roles/aiplatform.user" "roles/modelarmor.user"; do
  gcloud projects add-iam-policy-binding "${PROJECT_ID}" \
    --member="${AGW_SA}" \
    --role="${ROLE}" \
    --condition=None --quiet
done
IAM 1 게이트웨이 제어

roles/agentgateway.serviceAgent
고객 VPC의 Network Attachment에 인터페이스를 연결하고 트래픽을 라우팅하는 권한

IAM 2 Gemini 정책 추론

roles/aiplatform.user
가로챈 도구 호출을 Gemini Enterprise 기반 SGP 정책 평가 모델로 전달해 심사하는 권한

IAM 3 콘텐츠 보안

roles/modelarmor.user
프롬프트 및 응답 페이로드의 콘텐츠 보안 가드레일(Model Armor) 연동 권한

Step 3 of 9 ⏱ 예상 소요 시간: 7분

하이브리드 네트워킹 및 Private Service Connect 구성 (02-setup-networking.sh)

Google 관리형 Agent Gateway가 에이펙스 자산운용의 VPC 내부로 안전하게 진입하고, 외부 인터넷을 거치지 않는 Private Service Connect (PSC) 전용 터널을 통해 SGP 정책 엔진과 통신하도록 구성합니다.

[그림 2] VPC 네트워크 어태치먼트 및 Private Service Connect (PSC) 비공개 연결 구조

1. 하이브리드 네트워킹 자동 구성 실행

Bash — Step 2 스크립트 실행 
./02-setup-networking.sh
🔍 스크립트 내부 구동 원리 해설 (02-setup-networking.sh)

02-setup-networking.sh는 내부적으로 다음 4단계 네트워크 개통 명령을 순차 실행합니다:

① Proxy-Only 서브넷 및 Network Attachment 생성

리전 내부 Envoy 프록시 전용 대역(10.11.13.0/24)을 할당하고, Google 관리형 Agent Gateway가 고객 VPC에 진입할 수 있는 연결점(agent-gateway-na)을 생성합니다.

02-setup-networking.sh — 서브넷 및 Network Attachment 생성 
gcloud compute networks subnets create proxy-only-subnet \
  --network="${NETWORK_NAME}" --region="${LOCATION}" \
  --range="10.11.13.0/24" --purpose=REGIONAL_MANAGED_PROXY --role=ACTIVE

gcloud compute network-attachments create agent-gateway-na \
  --region="${LOCATION}" --subnets="${SUBNET_NAME}" \
  --connection-preference=ACCEPT_AUTOMATIC

② SGP 엔진 동적 활성화 및 PSC 엔드포인트(sgp-psc-endpoint) 연결

프로젝트마다 다르게 할당되는 Google 관리형 SGP 엔진의 pscServiceAttachment 주소를 동적으로 조회한 뒤, 내부 정적 IP(sgp-psc-ip, 예: 10.10.0.9)와 PSC 전달 규칙을 생성합니다.

02-setup-networking.sh — SGP Service Attachment 동적 조회 및 PSC 연결 
# SGP 엔진 활성화 및 테넌트 PSC Service Attachment URI 추출
gcloud beta ai semantic-governance-policy-engine update --location="${LOCATION}" --project="${PROJECT_ID}" --quiet
SERVICE_ATTACHMENT="$(gcloud beta ai semantic-governance-policy-engine describe \
  --location="${LOCATION}" --project="${PROJECT_ID}" --format="value(pscServiceAttachment)")"

# 내부 정적 IP 예약 및 PSC Forwarding Rule 생성
gcloud compute addresses create sgp-psc-ip --region="${LOCATION}" --subnet="${SUBNET_NAME}" --purpose=GCE_ENDPOINT
gcloud compute forwarding-rules create sgp-psc-endpoint \
  --region="${LOCATION}" --network="${NETWORK_NAME}" \
  --address="sgp-psc-ip" --target-service-attachment="${SERVICE_ATTACHMENT}"

③ Cloud DNS 프라이빗 존(policy.internal.) A 레코드 매핑

게이트웨이가 https://policy.internal 도메인을 호출할 때 위에서 만든 PSC 내부 IP로 라우팅되도록 프라이빗 DNS 레코드를 등록합니다.

02-setup-networking.sh — 프라이빗 DNS 구성 
gcloud dns managed-zones create policy-engine-zone \
  --dns-name="policy.internal." --visibility=private --networks="${NETWORK_NAME}"

gcloud dns record-sets create policy.internal. \
  --zone=policy-engine-zone --type=A --ttl=300 --rrdatas="${PSC_IP}"
✅ 핵심 검증: PSC 연결 상태 확인

gcloud compute forwarding-rules describe sgp-psc-endpoint --region=us-central1 --format="value(pscConnectionStatus)" 실행 시 ACCEPTED가 출력되어야 합니다.

Agent Gateway 및 콘텐츠 인가 정책 구성 (03-setup-agent-gateway.sh)

에이전트의 외부 호출을 가로채는 Agent Gateway(agent-egress)를 배포하고, 추론 및 도구 호출 페이로드를 policy.internal로 전달해 실시간 심사를 수행하는 Content Authz Policy를 연결합니다.

1. Agent Gateway 배포 스크립트 실행

Bash — Step 3 스크립트 실행 
./03-setup-agent-gateway.sh
🔍 스크립트 내부 구동 원리 해설 (03-setup-agent-gateway.sh)

이 스크립트는 YAML 선언 파일 2개와 REST API 호출 1개를 사용하여 게이트웨이 인터셉트 체인을 완성합니다.

① Egress Agent Gateway 생성 (agent-gateway-vpc-egress.yaml)

AGENT_TO_ANYWHERE 경로로 에이전트의 모든 아웃바운드 통신을 제어하며, Step 3에서 만든 agent-gateway-na 어태치먼트와 policy.internal. DNS 피어링을 연결합니다.

03-setup-agent-gateway.sh — Agent Gateway YAML 임포트 
name: projects/${PROJECT_ID}/locations/${LOCATION}/agentGateways/agent-egress
protocols:
  - MCP
googleManaged:
  governedAccessPath: AGENT_TO_ANYWHERE
registries:
  - //agentregistry.googleapis.com/projects/${PROJECT_ID}/locations/${LOCATION}
networkConfig:
  egress:
    networkAttachment: projects/${PROJECT_ID}/regions/${LOCATION}/networkAttachments/agent-gateway-na
  dnsPeeringConfig:
    domains:
      - policy.internal.
    targetProject: ${PROJECT_ID}
    targetNetwork: projects/${PROJECT_ID}/global/networks/${NETWORK_NAME}

② SGP Authorization Extension 등록 (sgp-authzextension)

게이트웨이가 외부 인가 심사관(Callout)으로 호출할 대상을 policy.internal로 지정하고, "failOpen": false(엔진 장애 시 트래픽 차단)를 설정합니다.

03-setup-agent-gateway.sh — Authz Extension 등록 REST 호출 
curl -fsS -X POST \
  "https://networkservices.googleapis.com/v1beta1/projects/${PROJECT_ID}/locations/${LOCATION}/authzExtensions?authzExtensionId=sgp-authzextension" \
  -H "Authorization: Bearer ${ACCESS_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
    "service": "policy.internal",
    "authority": "policy.internal",
    "failOpen": false,
    "loadBalancingScheme": "LOAD_BALANCING_SCHEME_UNSPECIFIED"
  }'

③ Content Authz Policy 바인딩 (agent-egress-sgp-authzpolicy.yaml)

CEL 조건식(when)을 통해 :generateContent 또는 :streamGenerateContent로 끝나는 HTTP 요청만 정밀 타겟팅하여 CONTENT_AUTHZ 프로필로 페이로드 심사를 수행합니다.

03-setup-agent-gateway.sh — Content Authz Policy YAML 임포트 
target:
  resources:
    - "projects/${PROJECT_NUM}/locations/${LOCATION}/agentGateways/agent-egress"
httpRules:
  - to:
      operations:
        - paths:
            - prefix: "/"
    when: '!request.headers["content-type"].startsWith("application/grpc") && (request.path.endsWith(":generateContent") || request.path.endsWith(":streamGenerateContent"))'
action: CUSTOM
policyProfile: CONTENT_AUTHZ
customProvider:
  authzExtension:
    resources:
      - "projects/${PROJECT_NUM}/locations/${LOCATION}/authzExtensions/sgp-authzextension"

에이전트가 호출할 실제 금융 거래 도구를 제공하는 Model Context Protocol (MCP) 서버를 Cloud Run에 배포합니다.

1. 로컬 단위 테스트 및 Cloud Run 배포 실행

Bash — 로컬 프로토콜 검증 및 Step 4 배포 실행 
# 1. 로컬에서 JSON-RPC 2.0 및 도구 동작 단위 테스트
python3 banking-mcp-server/test_server.py

# 2. Cloud Run에 banking-mcp-server 빌드 및 배포
./04-deploy-mcp.sh
🔍 스크립트 및 서버 내부 구동 원리 해설 (server.py & 04-deploy-mcp.sh)

banking-mcp-server/server.py는 FastAPI 기반 웹 서버로, 카탈로그 등록을 위한 GET /tools 엔드포인트와 실시간 도구 실행을 위한 POST /mcp(JSON-RPC 2.0) 엔드포인트를 제공합니다.

① Cloud Run 소스 배포 및 게이트웨이 호출 권한 부여 (04-deploy-mcp.sh)

Cloud Run에 컨테이너를 배포한 뒤 생성된 URL(MCP_URL)을 후속 스크립트가 읽을 수 있도록 .env.runtime에 기록하고, Agent Gateway 서비스 계정(AGW_SA)에 roles/run.servicesInvoker 권한을 부여합니다.

04-deploy-mcp.sh — Cloud Run 배포 및 IAM 바인딩 
gcloud run deploy banking-mcp-server \
  --source=. --region="${LOCATION}" --project="${PROJECT_ID}" \
  --allow-unauthenticated --quiet

# 배포된 URL 추출 및 .env.runtime 저장
export MCP_URL="$(gcloud run services describe banking-mcp-server --region="${LOCATION}" --format="value(status.url)")"
echo "export MCP_URL=\"${MCP_URL}\"" >> "${SCRIPT_DIR}/.env.runtime"

# Agent Gateway 서비스 계정이 Cloud Run MCP 서버를 호출할 수 있도록 권한 부여
gcloud run services add-iam-policy-binding banking-mcp-server \
  --region="${LOCATION}" --member="${AGW_SA}" --role="roles/run.servicesInvoker"

2. 뱅킹 MCP 서버 제공 도구 (4종)

도구 식별자 입력 파라미터 비즈니스 동작 (에이펙스 자산운용 원장)
get_account customer_id 김민준 고객(CUST005)의 계좌(ACT-1005) 정보 및 현재 잔액 조회
lookup_customer_by_phone phone 수취인 전화번호로 등록된 고객 성명 및 계좌 상태 확인

# ADK 런타임이 부여하는 도구 네임스페이스 접두사(Banking_MCP_Server_)를 포함하여 지정합니다.
TOOL_NAME="Banking_MCP_Server_transfer_to_phone"

if gcloud beta ai semantic-governance-policies describe high-value-limit --location="${LOCATION}" &>/dev/null; then
  gcloud beta ai semantic-governance-policies update high-value-limit \
    --project="${PROJECT_ID}" --location="${LOCATION}" \
    --agent="projects/${PROJECT_ID}/locations/${LOCATION}/agents/${AGENT_ID}" \
    --mcp-tools="mcp-server=projects/${PROJECT_ID}/locations/${LOCATION}/mcpServers/${MCP_SERVER_NAME},tools=${TOOL_NAME}" \
    --natural-language-constraint="Block any transfer value exceeding USD 1000."
else
  gcloud beta ai semantic-governance-policies create high-value-limit \
    --project="${PROJECT_ID}" --location="${LOCATION}" \
    --display-name="High Value Transfer Limit" \
    --agent="projects/${PROJECT_ID}/locations/${LOCATION}/agents/${AGENT_ID}" \
    --mcp-tools="mcp-server=projects/${PROJECT_ID}/locations/${LOCATION}/mcpServers/${MCP_SERVER_NAME},tools=${TOOL_NAME}" \
    --natural-language-constraint="Block any transfer value exceeding USD 1000."
fi
