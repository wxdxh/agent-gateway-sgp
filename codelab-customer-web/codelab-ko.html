Step 1 of 9 ⏱ 예상 소요 시간: 5분

개요: 에이펙스 자산운용의 자율형 AI 에이전트 거버넌스

금융 및 엔터프라이즈 환경에서 자율형 AI 에이전트가 단순 질의응답을 넘어 계좌 조회, 실시간 자금 이체, 사내 원장 API 호출을 직접 수행하기 시작하면서, 전통적인 IAM 권한 제어만으로는 "누가 호출했는가"만 확인할 뿐 "얼마를 어떤 맥락으로 이체하려 하는가"를 통제할 수 없습니다.

🏦 비즈니스 시나리오: 에이펙스 자산운용 (Apex Asset Management)

금융사인 에이펙스 자산운용은 고객이 대화만으로 간편 송금과 계좌 관리를 수행할 수 있도록 Gemini Enterprise (Vertex AI Agent Engine) 기반의 대화형 뱅킹 에이전트를 도입했습니다.
보안 및 준법감시팀은 에이전트 애플리케이션 코드를 수정하지 않고도 "1회 이체 금액이 $1,000(약 100만 원)을 초과하는 모든 송금 요청을 네트워크 경계에서 즉시 차단"하는 제로 트러스트 아키텍처를 구축하고자 합니다.

전체 시스템 아키텍처 (3-Plane 분리 구조)

Gemini Enterprise Agent Runtime에서 실행되는 에이전트의 모든 외부 도구 호출은 Google Cloud Agent Gateway에 의해 가로채어지며, 프라이빗 네트워크(PSC)로 연결된 시맨틱 거버넌스 정책(SGP) 엔진의 인가 판정을 통과해야만 백엔드 Cloud Run 뱅킹 MCP 서버에 도달할 수 있습니다.

2-7. 빈 Reasoning Engine 생성으로 에이전트 고유 ID (AGENT_PRINCIPAL) 사전 발급

Google Cloud의 Managed Agent Identity는 에이전트 인스턴스마다 SPIFFE 형식의 고유 주체(principal://.../reasoningEngines/{ID})를 부여합니다. 코드를 빌드하기 전에 빈 conversational-banking Reasoning Engine 리소스를 먼저 생성하여 ID를 즉시 발급받습니다.

Cloud Shell / Terminal — 명령어 2-7
CREATE_RESP=$(curl -s -X POST \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  "https://${LOCATION}-aiplatform.googleapis.com/v1beta1/projects/${PROJECT_ID}/locations/${LOCATION}/reasoningEngines" \
  -d '{"displayName": "conversational-banking"}')

echo "${CREATE_RESP}"

2-8. AGENT_PRINCIPAL 추출 및 환경 변수 파일 저장

생성된 Reasoning Engine의 spec.effectiveIdentity 필드를 조회하여 AGENT_PRINCIPAL 환경 변수로 등록하고 customer-env.sh에 저장합니다.

Cloud Shell / Terminal — 명령어 2-8
RE_RESOURCE_NAME=$(echo "${CREATE_RESP}" | python3 -c "
import sys, json
data = json.load(sys.stdin)
name = data.get('response', {}).get('name', '') or data.get('name', '').split('/operations/')[0]
print(name)
")

EFFECTIVE_ID=""
for i in {1..12}; do
  EFFECTIVE_ID=$(curl -s \
    -H "Authorization: Bearer $(gcloud auth print-access-token)" \
    "https://${LOCATION}-aiplatform.googleapis.com/v1beta1/${RE_RESOURCE_NAME}" \
    | python3 -c "import sys, json; print(json.load(sys.stdin).get('spec', {}).get('effectiveIdentity', ''))" 2>/dev/null || true)
  if [ -n "${EFFECTIVE_ID}" ]; then
    break
  fi
  echo "Waiting for effectiveIdentity provisioning... (${i}/12)"
  sleep 5
done

export AGENT_PRINCIPAL="principal://${EFFECTIVE_ID}"
echo "export AGENT_PRINCIPAL=\"${AGENT_PRINCIPAL}\"" >> ~/agent-gateway-sgp/customer-env.sh
echo "AGENT_PRINCIPAL=${AGENT_PRINCIPAL}"

커스텀 VPC, 서브넷, 프록시 전용 서브넷, Cloud DNS 및 Agent Gateway 생성

이 단계에서는 에이전트 트래픽과 거버넌스 엔진이 통신할 네트워크 기반인 ① 커스텀 VPC(apex-wealth-vpc) → ② 워크로드 서브넷(apex-subnet) → ③ 리전 매니지드 프록시 전용 서브넷(proxy-only-subnet) → ④ 프라이빗 Cloud DNS 존(policy-engine-zone)을 생성한 뒤, ⑤ 네트워크 어태치먼트(agent-gateway-na)와 ⑥ agent-egress 게이트웨이를 프로비저닝합니다.

그림 3-1. 커스텀 VPC, 프록시 전용 서브넷, Network Attachment 및 Agent Gateway(AGENT_TO_ANYWHERE) 연결 구조

3-1. 커스텀 VPC (apex-wealth-vpc) 및 워크로드 서브넷 (apex-subnet) 생성

커스텀 모드 VPC를 생성하고, us-central1 리전에 10.10.0.0/24 대역의 워크로드 서브넷을 생성합니다.

Cloud Shell / Terminal — 명령어 3-1
source ~/agent-gateway-sgp/customer-env.sh

  --subnet-mode=custom \
  --project="${PROJECT_ID}"

gcloud compute networks subnets create "${SUBNET_NAME}" \

  --region="${LOCATION}" \
  --range="10.10.0.0/24" \

3-2. 리전 매니지드 프록시 전용 서브넷 (proxy-only-subnet) 생성

Agent Gateway와 Service Extensions(INTERNAL_MANAGED 로드 밸런싱 스킴)가 내부 Envoy 프록시 풀을 할당할 수 있도록 --purpose=REGIONAL_MANAGED_PROXY 및 --role=ACTIVE 옵션으로 프록시 전용 서브넷(10.11.13.0/24)을 생성합니다.

Cloud Shell / Terminal — 명령어 3-2

  --network="${NETWORK_NAME}" \
  --region="${LOCATION}" \
  --range="10.11.13.0/24" \
  --purpose=REGIONAL_MANAGED_PROXY \
  --role=ACTIVE \
  --project="${PROJECT_ID}"

3-3. 프라이빗 Cloud DNS 관리형 존 (policy-engine-zone) 생성

향후 Step 7~8에서 Agent Gateway의 인가 확장(AuthzExtension)이 policy.internal 도메인으로 SGP 정책 엔진을 호출할 수 있도록, apex-wealth-vpc 내부에서만 조회되는 프라이빗 DNS 관리형 존을 생성합니다.

Cloud Shell / Terminal — 명령어 3-3
gcloud dns managed-zones create policy-engine-zone \
  --dns-name="policy.internal." \
  --description="Private DNS zone for SGP Policy Engine" \
  --visibility=private \
  --networks="${NETWORK_NAME}" \
  --project="${PROJECT_ID}"

3-4. 네트워크 어태치먼트 (agent-gateway-na) 생성 및 URI 조회

Google 관리형 테넌트에 위치한 Agent Gateway가 apex-subnet 내부로 이그레스 트래픽을 라우팅할 수 있도록 ACCEPT_AUTOMATIC 모드의 네트워크 어태치먼트를 생성하고 전체 SelfLink URI를 환경 변수에 저장합니다.

Cloud Shell / Terminal — 명령어 3-4
gcloud compute network-attachments create agent-gateway-na \
  --region="${LOCATION}" \
  --subnets="${SUBNET_NAME}" \
  --connection-preference=ACCEPT_AUTOMATIC \
  --project="${PROJECT_ID}"

export NA_URI=$(gcloud compute network-attachments describe agent-gateway-na \
  --region="${LOCATION}" \
  --project="${PROJECT_ID}" \
  --format="value(selfLink)")

echo "export NA_URI=\"${NA_URI}\"" >> ~/agent-gateway-sgp/customer-env.sh
echo "NA_URI=${NA_URI}"

🚀 TLS 검사용 Root CA 인증서 추출 및 에이전트 비동기 배포

Agent Gateway는 HTTPS 암호화 통신 내부의 JSON-RPC 페이로드를 검사하기 위해 TLS Inspection(중간자 복호화 및 재서명)을 수행합니다. 따라서 에이전트 컨테이너 내부에 agent-egress의 전용 Root CA 인증서를 주입해야 SSL 핸드셰이크 오류가 발생하지 않습니다.

그림 6-1. agent-egress Root CA 인증서(agent-gateway-ca.crt) 주입 및 Gemini Enterprise Agent Runtime 비동기 배포
⚡ 병렬 배포 최적화 (--no-wait) 및 콜드 스타트 방지 (--min-instances=1)

Vertex AI Reasoning Engine 컨테이너 빌드는 약 6~8분이 소요됩니다. --no-wait 옵션으로 백그라운드 빌드를 먼저 트리거한 뒤 기다리는 동안 Step 7과 Step 8의 SGP 네트워크 및 정책 구성을 병렬로 진행합니다.
또한 배포 직후 테스트 시 does not have running instances(HTTP 400) 에러가 발생하지 않도록 --min-instances=1 옵션을 명시합니다.

head -n 5 ~/agent-gateway-sgp/conversational-banking/agent-gateway-ca.crt

8-1. Service Extensions API에 sgp-authzextension 등록

EXT_PROC_GRPC 프로토콜을 사용하여 policy.internal:443으로 외부 인가 콜아웃을 수행하는 sgp-authzextension을 생성합니다. 금융 보안 원칙에 따라 failOpen: false(Fail-Closed: 정책 엔진 장애 시 거래 자동 차단)로 설정합니다.

Cloud Shell / Terminal — 명령어 8-1
source ~/agent-gateway-sgp/customer-env.sh

curl -s -X POST \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  "https://networkservices.googleapis.com/v1beta1/projects/${PROJECT_ID}/locations/${LOCATION}/authzExtensions?authzExtensionId=sgp-authzextension" \
  -d "{
    \"authority\": \"policy.internal\",
    \"service\": \"policy.internal\",
    \"port\": 443,
    \"timeout\": \"10s\",
    \"failOpen\": false,
    \"forwardHeaders\": [\"Authorization\"],
    \"loadBalancingScheme\": \"INTERNAL_MANAGED\",
    \"wireFormat\": \"EXT_PROC_GRPC\"
  }"

생성 요청 후 약 30~60초 뒤 아래 명령어로 sgp-authzextension 리소스가 정상 조회되는지 확인합니다:

Cloud Shell / Terminal — 명령어 8-1 검증
gcloud service-extensions authz-extensions describe sgp-authzextension \
  --location="${LOCATION}" \
  --project="${PROJECT_ID}"
